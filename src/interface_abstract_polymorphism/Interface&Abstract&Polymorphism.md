[抽象クラスとは (추상 클래스란)]
* `추상 메서드를 1개 이상 가진 클래스`를 의미
* 추상 메서드란, `정의만 있고 처리를 작성하지 않는` 메서드를 의미

[구문 (構文)]
* 추상 클래스 정의 구문
  修飾子 `abstract` class クラス名 {}
* 추상 메서드 정의 구문
  修飾子 `abstract` 戻り値 メソッド名(引数リスト);

[Point]
* 추상 메서드는 내용이 없기 때문에 `세미콜론으로 끝`난다
* abstract 수식어의 기술 위치에 주의한다

- 어째서 처리 내용이 없는 메서드가 필요할까?
  ⇒ 추상 클래스를 사용함으로써, `어느 정도의 구현 규칙을 만들 수 있다!`

[구조 및 예시]
- 【추상 클래스】
    - 동물 클래스
        - 추상 메서드: animalType
        - 추상 메서드: cry

- 【実装 (구현, implements)】
    - 고양이 클래스
        - 抽象メソッド : animalType
        - 抽象メソッド : cry
    - 개 클래스
        - 抽象メソッド : animalType
        - 抽象メソッド : cry

[Point]
- 추상 클래스가 있음으로써, 메서드 이름이나 메서드 사용법을 어느 정도 지정할 수 있다

[인터페이스란 (インターフェースとは)]
* 공개해야 할 필요한 조작을 모아둔 것
* 특정 동작을 수행하기 위해 메서드 작성법을 정의하는 것
* 인터페이스를 구현한 클래스를 구현 클래스라고 부른다

[버전별 사양]
* _SE7까지의 사양_
    * `추상 메서드`와 `static 상수만` 선언 가능
* _SE8 이후의 사양_
    * 위의 내용 외에, 구현을 가지는 구체 메서드(`디폴트 메서드·static 메서드`)도 정의 가능하게 됨


[인터페이스의 정의·상속·구현 구문]

* **인터페이스 정의 구문**
  `修飾子 interface インターフェース名 {}`

* **인터페이스를 상속한 인터페이스 정의 구문**
  `修飾子 interface インターフェース名 extend 継承するインターフェース名{}`

* **인터페이스 구현 구문**
  `修飾子 class クラス名 implements インターフェース名 {}`

* **인터페이스를 복수 구현하는 구문**
  `修飾子 class クラス名 implements インターフェース名1, インターフェース名2 {}`

* **Point**
    * 인터페이스를 복수 구현하는 경우에는 콤마로 구분합니다



[인터페이스 사용 예 (インターフェースの使用例)]

* **인터페이스 정의 (インターフェースの定義)**
  
public interface Life {
    void cry();
}

* **인터페이스 구현 (インターフェースの実装)**

public class Dog `implements` Life {
    @Override
    public void cry() {
        System.out.println("ワン");
    }
}


[추상 클래스와 인터페이스의 특징 비교]

* **특징**
    * **アクセス修飾子 (접근 제어자)**
        * `interface`: public만 가능
        * `abstract` (추상 클래스): private / protected가 사용 가능
    * **多重継承 (다중 상속)**
        * `interface`: 可能 (가능)
        * `abstract`: 不可能 (불가능)
    * **メソッドのオーバーライド (메서드 오버라이드)**
        * `interface`: 파생 클래스 쪽에서 필요한 메서드만 선택할 수 있다
        * `abstract`: 자식 클래스는 모든 추상 메서드를 오버라이드할 의무를 가진다

* **정리 및 특징**
    * Java 언어에서는 추상 클래스의 다중 상속이 금지되어 있으므로, 이를 보완하기 위해 인터페이스가 이용된다



[추상 클래스와 인터페이스 병용]

* **추상 클래스 상속 + 인터페이스 구현 구문**
  `修飾子 class クラス名 extend 抽象クラス名 implements インターフェース名 {}`

* **추상 클래스 상속 + 복수 인터페이스 구현 구문**
  `修飾子 class クラス名 extend 抽象クラス名 implements インターフェース名1, インターフェース名2 {}`

* **Point**
    * 반드시 `extend` 키워드를 먼저 기술합니다

[다형성 (Polymorphism)]

* **정의 (意味)**
    * "다양성", "다태성", "다상성"이라는 의미를 가짐
    * 객체지향 언어에서는 공통의 인터페이스를 가진 조작이라도 객체마다 행동이나 동작이 다른 것을 가리킴
    * ↳ 오버라이드·오버로드로 실현

[다형성의 장점]
* **① 코드가 깔끔해짐**
    * ⇒ 같은 내용을 가진 클래스에 `여러 번 같은 코드를 작성하지 않아도 됨`
* **② 중복된 메서드의 변경에도 유연하게 대응할 수 있음**
    * ⇒ 처리 변경 시에는 `부모 클래스의 메서드를 고치는 것만으로 끝남`

코드예

// 인터페이스 정의
interface Parts {
    void print();
}

// 동일한 인터페이스를 구현하는 첫 번째 클래스
class Machine1 implements Parts { // 같은 인터페이스를 구현
    @Override
    public void print() {
        System.out.println("RED"); // 처리 내용은 다름
    }
}

// 동일한 인터페이스를 구현하는 두 번째 클래스
class Machine2 implements Parts { // 같은 인터페이스를 구현
    @Override
    public void print() {
        System.out.println("BLUE"); // 처리 내용은 다름
    }
}



public class Test {
    public static void main(String[] args) {
            Machine1 m1 = new Machine1();
            Machine2 m2 = new Machine2();
            exe01(m1); // RED 同じメソッドだが結果は異なる
            exe01(m2); // BLUE 同じメソッドだが結果は異なる
        }
        // 同じインターフェース型でアクセスできる
        static void exe01(Parts m) { // `引数の型はインターフェース型`
            m.print();
        }
}
